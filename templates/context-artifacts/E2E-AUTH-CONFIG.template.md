# E2E Auth Configuration

> Generated by `playwright-setup` agent. Defines authentication strategy for Playwright E2E tests.

## Auth Config File

**Location:** `e2e/config/auth.config.json`

```json
{
  "strategy": "none",
  "storageStatePath": "e2e/auth/storage-state.json",

  "credentials": {
    "loginUrl": "/login",
    "usernameSelector": "[data-testid='username-input']",
    "passwordSelector": "[data-testid='password-input']",
    "submitSelector": "[data-testid='login-button']",
    "successIndicator": "[data-testid='dashboard']",
    "usernameEnvVar": "E2E_AUTH_USERNAME",
    "passwordEnvVar": "E2E_AUTH_PASSWORD"
  },

  "oauth": {
    "provider": "google",
    "loginButtonSelector": "[data-testid='google-login']",
    "setupMode": "manual",
    "notes": "Run 'npx ts-node e2e/scripts/auth-setup.ts' to login manually and save storageState"
  }
}
```

## Strategy Reference

| Strategy | When to Use | How It Works |
|----------|-------------|--------------|
| `none` | Public pages, no auth needed | Skip auth entirely |
| `credentials` | Username/password form login | Auto-fill form from env vars, save storageState |
| `oauth` | Google, MSAL, Azure AD, SSO | Manual login in visible browser, save storageState |
| `storageState` | Pre-saved browser state | Load existing storageState file directly |

## Environment Variables

Create `.env` file (gitignored) in project root:

```bash
# For credentials strategy
E2E_AUTH_USERNAME=testuser@example.com
E2E_AUTH_PASSWORD=your-password-here

# For oauth strategy (optional — used by auth-setup script)
E2E_OAUTH_EMAIL=testuser@gmail.com
```

**Security:** NEVER commit passwords to the repository. The `auth.config.json` only contains selectors and env var names — actual credentials are in `.env` (gitignored).

## Usage

### Credentials Strategy

1. Set `"strategy": "credentials"` in `auth.config.json`
2. Update selectors to match your login form
3. Add credentials to `.env`
4. Run tests — `globalSetup` auto-fills form and saves state

### OAuth Strategy

1. Set `"strategy": "oauth"` in `auth.config.json`
2. Run: `npx ts-node e2e/scripts/auth-setup.ts`
3. Login manually in the visible browser
4. State is saved to `e2e/auth/storage-state.json`
5. Run tests — they use saved state automatically
6. When state expires (~30 days), re-run step 2

### StorageState Strategy

1. Set `"strategy": "storageState"` in `auth.config.json`
2. Manually place a valid `storage-state.json` in `e2e/auth/`
3. Tests use it directly

## Playwright Config Integration

```typescript
// playwright.config.ts
import { defineConfig } from '@playwright/test';

export default defineConfig({
  globalSetup: require.resolve('./e2e/helpers/auth.helper'),
  use: {
    storageState: 'e2e/auth/storage-state.json',
  },
});
```

## Notes

- `storageState` works for ALL auth types (MSAL, OAuth, SSO, JWT, Cookie-based)
- OAuth automated login is unreliable (Google CAPTCHA, 2FA) — always use manual setup
- StorageState captures: cookies + localStorage + sessionStorage
- Typical expiry: ~30 days for OAuth tokens, varies by provider
- `.auth/` and `e2e/auth/` directories should be in `.gitignore`
