### Allowed Dependencies

| From (Importer) | May Import From | Must NOT Import From |
|-----------------|----------------|---------------------|
| Infrastructure | Application, Domain | - |

| Domain | (nothing external) | Application, Infrastructure |

### Concrete Rules

1. **Domain layer has ZERO external dependencies.** No framework imports, no database drivers, no HTTP libraries. Domain contains only: entities, value objects, domain services, repository interfaces (ports).

2. **Application layer depends only on Domain.** Application contains: use cases, application services, DTOs. It imports domain entities and repository interfaces. It does NOT import concrete infrastructure implementations.

3. **Infrastructure layer implements domain interfaces.** Infrastructure contains: repository implementations, external API clients, database adapters, framework controllers. It imports from both domain (to implement interfaces) and application (to wire use cases).

### Cross-Context Rules

1. **No direct imports between bounded contexts.** Contexts communicate only through defined interfaces (events, shared kernel, or API calls).
2. **Shared kernel must be minimal.** Only truly shared concepts (e.g., UserId) belong in the shared kernel.
3. **Each context owns its data.** No context directly queries another context's database tables.
